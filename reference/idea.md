# Emotion DJ: CAA感情空間を用いた「言葉にならない感情」の言語化UI構想

## 1. コンセプト

本システムは、ユーザーがうまく言葉にできない感情を、LLM内部の感情表現空間を操作することで、より正確に言語化するためのインターフェースである。

ユーザーは、自分の感情を最初から `joy`、`sadness`、`anger`、`fear` のような既存の感情名で選ぶ必要はない。代わりに、DJブースのようなUIを通じて、感情の明るさ、強度、緊張感、主体感、温かさ、抵抗感などを連続的に調整する。

LLMは、その調整結果をもとに、ユーザーの曖昧な内的状態を自然言語として再構成する。

目的は、感情を分類することではなく、ユーザーが「これが言いたかった」と感じられる文章を生成することである。

---

## 2. 背景仮説

通常、感情は以下のような名前付きカテゴリとして扱われる。

* joy
* sadness
* anger
* fear
* trust
* disgust
* anticipation
* surprise

しかし、人間の実際の感情は、これらの離散カテゴリだけでは表現しきれない。

たとえば、以下のような感情がある。

* 嬉しいが、同時に失うのが怖い
* 怒っているが、本当は悲しい
* 相手を信じたいが、どこか警戒している
* 前向きではあるが、不安が混ざっている
* 懐かしくて温かいが、少し苦しい

これらは単一の感情名では表しにくい。

本研究の仮説は、LLM内部の感情表現も、最初から `joy` や `fear` のような離散ラベルとして存在しているのではなく、より低次元で連続的な感情空間として表現されている、というものである。

人間が `joy` や `sadness` と呼んでいるものは、その連続空間上のプロトタイプ的な領域に対して後から付けられた名前にすぎない可能性がある。

---

## 3. CAAを使う理由

本システムでは、LLMの残差ストリームそのものではなく、CAA（Contrastive Activation Addition）によって得られる感情方向を用いる。

残差ストリームを直接分析すると、以下の要素が混ざりやすい。

* 文体
* 語彙
* トピック
* 文の長さ
* プロンプト形式
* ソーステキスト固有の内容

一方で、CAAは次のように定義される。

```text
CAA_emotion = mean(h_emotion_rewrite - h_neutral)
```

つまり、ベーステキストから感情的に書き換えたテキストへの変化方向を平均する。

これにより、個別の文脈や語彙に依存しにくい「感情変化そのものの方向」を抽出しやすくなる。

---

## 4. 感情CAAの分解

実験結果から、感情CAAには大きく2つの成分があると考えられる。

```text
emotion CAA
= common emotionalization direction
+ emotion-specific residual direction
```

### 4.1 Common emotionalization direction

全ての感情CAAに共通する方向。

これは、特定の感情というより、

* 文章を感情的にする
* 内面を表出する
* 感情的なニュアンスを増やす
* 中立文を感情表現に変える

といった一般的な「感情化」方向だと考えられる。

### 4.2 Emotion-specific residual direction

共通の感情化方向を除去したあとに残る、各感情に固有の方向。

ここに、`joy`、`sadness`、`anger`、`fear` などの相対的な配置が現れる。

この残差空間は、8つの独立したカテゴリというより、3〜4次元程度の低次元連続空間として表現されている可能性がある。

---

## 5. システム設計方針

本システムでは、以下の2つの方法を組み合わせる。

---

## 6. 方法1: 共通の低次元感情空間を使う

共通方向除去後の感情CAAにPCA/SVDを適用し、低次元の共通感情空間を作る。

この空間は、DJブースUIのメインミキサーとして使う。

たとえば、次のようなノブに対応させる。

```text
PC1: 明るさ / 快・不快 / positive-negative
PC2: 高ぶり / 緊張 / arousal
PC3: 主体感 / コントロール感 / dominance
PC4: 接近・回避 / approach-avoidance
PC5: 社会的温かさ / social warmth
```

実際にどのPCがどの心理軸に対応するかは、VADスコアや生成結果を用いて検証する。

### UI上の例

```text
Main Mixer

- Brightness      暗い  ←→  明るい
- Intensity       静か  ←→  高ぶっている
- Control         無力  ←→  主体的
- Tension         緩い  ←→  張り詰めている
- Warmth          冷たい ←→  温かい
- Distance        離れたい ←→  近づきたい
```

この方法の利点は、ユーザーが最初から感情名を選ばなくてよいことである。

ユーザーは「これは悲しみなのか怒りなのか」と考える代わりに、「もう少し温かく」「もっと緊張感を下げる」「少しだけ抵抗感を残す」のように操作できる。

---

## 7. 方法2: 各感情ごとの局所低次元空間を使う

各感情について、per-source deltaまたは個別CAAの分布にPCAを行い、その感情内部の局所低次元空間を作る。

たとえば、`sadness` の内部にも複数の軸がある可能性がある。

```text
sadness_PC1: 喪失感
sadness_PC2: 自責感
sadness_PC3: 諦め / 疲労感
```

`anger` なら、

```text
anger_PC1: 攻撃的怒り
anger_PC2: 正義感 / 抗議
anger_PC3: 傷つきから来る怒り
```

`fear` なら、

```text
fear_PC1: 危険への警戒
fear_PC2: 不確実性
fear_PC3: 見捨てられ不安
```

のような下位構造が現れる可能性がある。

この局所空間は、DJブースUIにおける「エフェクター」や「音色調整」に相当する。

---

## 8. 名前にできない感情の生成

方法2を使うと、複数の感情の局所PCを組み合わせることで、既存の感情名では表しにくい複合感情を定義できる。

例:

```text
joy_PC1 + sadness_PC2
```

これは、以下のような感情に対応する可能性がある。

```text
嬉しいが、少し切ない
温かいが、失われる予感がある
懐かしく、同時に寂しい
```

別の例:

```text
anger_PC2 + sadness_PC1
```

これは、

```text
怒っているが、本当は傷ついている
抗議したいが、同時に諦めもある
悔しさと悲しみが混ざっている
```

のような感情を表す可能性がある。

さらに、

```text
fear_PC1 + anticipation_PC1
```

は、

```text
不安だが、期待もしている
怖いけれど、先に進みたい
落ち着かない前向きさ
```

のような感情になるかもしれない。

## 9. UIイメージ

本システムのUIは、感情を選択するフォームではなく、DJブースのようなミキサーとして設計する。

### 9.1 メインミキサー

共通低次元感情空間を操作する。

```text
Brightness     [-----|---------]
Intensity      [--------|------]
Control        [---|-----------]
Tension        [----------|----]
Warmth         [------|--------]
Distance       [----|----------]
```

### 9.2 Emotion Texture

各感情のプロトタイプ方向や局所PCを調整する。

```text
Joy Warmth          [-----|---------]
Sadness Depth       [--------|------]
Fear Tension        [---|-----------]
Anger Resistance    [------|--------]
Trust Softness      [---------|-----]
Disgust Rejection   [--|------------]
Anticipation Pull   [-------|-------]
Surprise Disruption [----|----------]
```

### 9.3 出力例

ユーザー入力:

```text
なんか嬉しいんだけど、同時に少し怖い。うまく言えない。
```

UI調整後の出力:

```text
嬉しさは確かにある。でもそれは、手放しで明るいものではなくて、
大切なものが近づいてくるほど、それを失う可能性まで見えてしまうような感覚に近い。
楽しみにしているのに、どこかで身構えている。
前に進みたい気持ちと、傷つきたくない気持ちが同時にある。
```

## 10. 実験計画

### 実験1: 低次元軸の解釈可能性

共通方向除去後のCAA空間に対してPCAを行い、PC1〜PC5を得る。

各PC方向にsteeringを行う。

```text
base + α * PC1
base - α * PC1
base + α * PC2
base - α * PC2
...
```

αは以下のように変化させる。

```text
-2, -1, -0.5, 0, 0.5, 1, 2
```

生成された文章を以下の観点で評価する。

* valence
* arousal
* dominance
* certainty
* approach / avoidance
* social warmth
* self-blame / other-blame
* clarity
* naturalness

目的は、各PCが人間にとって意味のあるUIノブとして使えるかを検証することである。

---

### 実験2: VADとの対応

共通低次元CAA空間のPC座標と、VADスコアの対応を見る。

検証すること:

```text
PC1 ≈ valence か？
PC2 ≈ arousal か？
PC3 ≈ dominance か？
VADでは説明できない残差は何次元あるか？
```

やること:

```text
1. emotion CAA residual のPC座標を計算
2. 各感情の平均VADスコアと相関を取る
3. per-source delta residual からVADを回帰
4. VADからCAA residualを再構成
5. emotion label分類とVAD回帰の汎化性能を比較
```

VADだけでかなり説明できるなら、UIの基本ノブはVADに近くなる。

VADでは説明できない残差が大きいなら、その残差こそが「名前にしにくい感情ニュアンス」を表す可能性がある。

---

### 実験3: 局所感情PCの意味づけ

各感情について、per-source delta residual にPCAを行い、local PCを得る。

例:

```text
sadness_PC1
sadness_PC2
sadness_PC3
```

それぞれのPC方向にsteeringを行い、生成文の変化を観察する。

評価者に以下を尋ねる。

```text
このPC方向はどんな感情の違いに見えるか？
同じsadnessでも、どのようなサブタイプに分かれているか？
既存の感情名で表せるか？
一言で表せない場合、どのように説明できるか？
```

目的は、各感情内部の局所PCが、感情サブタイプとして解釈可能かを調べることである。

---

### 実験4: 複合感情ベクトルの生成

複数の感情PCを組み合わせて、名前にしにくい感情を生成する。

例:

```text
joy_PC1 + sadness_PC1
joy_PC1 + fear_PC2
anger_PC1 + sadness_PC2
trust_PC1 + fear_PC1
anticipation_PC1 + sadness_PC1
```

これらのベクトルでsteeringを行い、生成文を評価する。

評価項目:

```text
この感情は自然か？
既存の単一感情名で十分に表せるか？
複数の感情が混ざっているように見えるか？
どのような言葉で説明できるか？
ユーザーにとって「言葉にしにくい感情」の表現として有用か？
```

成功例:

```text
嬉しいが、同時に失うのが怖い
怒っているが、本当は悲しい
信じたいが、警戒している
懐かしいが、少し苦しい
前向きだが、どこか不安
```

---

### 実験5: UIによる感情言語化の有効性

ユーザーに、うまく言葉にできない感情を短く入力してもらう。

例:

```text
なんか重い感じがする。でも悲しいだけではない。
嬉しいはずなのに、どこか落ち着かない。
相手に怒っている気もするけど、本当は寂しいのかもしれない。
```

比較条件:

```text
A. 通常LLM
B. 感情ラベル選択式LLM
C. CAA DJブースUI
D. CAA DJブースUI + 局所感情PC
```

ユーザー評価:

```text
自分の感情に近い
言葉にできなかった部分が表現されている
決めつけられている感じが少ない
読み返して違和感が少ない
自分で編集しやすい
もう一度使いたい
```

目的は、CAAベースの連続感情UIが、通常のLLMや感情ラベル選択式UIよりも、ユーザーの内的状態の言語化に役立つかを検証することである。

## 11. システムの階層モデル

最終的なシステムは、以下のような階層で構成する。

```text
Level 0:
Common emotionalization direction
= 感情を帯びた言語化にする

Level 1:
Global affective subspace
= 明るさ、高ぶり、主体感、接近/回避などの基本ノブ

Level 2:
Emotion prototype directions
= joy, sadness, anger, fear などの中心方向

Level 3:
Local emotion subspaces
= sadnessの中の自責、angerの中の抗議、joyの中の切なさなど

Level 4:
User-specific calibration
= そのユーザーにとって「しっくりくる」表現への調整
```

UI上で直接見せるのは、主に Level 1 と Level 2 でよい。

Level 3 は「texture」「depth」「grain」「tone」などの形で裏側に持つ。

---

## 12. MVP案

最初のMVPでは、以下の構成にする。

```text
1. 共通方向除去済みCAAからPC1〜PC3を作る
2. PC1〜PC3をスライダー化する
3. joy / sadness / anger / fear の4感情だけ texture knob として追加する
4. ユーザーがスライダーを動かすと文章がリアルタイムに変わる
5. ユーザーの「近い / 遠い」フィードバックでベクトルを調整する
```

最初から8感情すべてを見せる必要はない。

むしろ、以下のような抽象ノブの方がユーザーにとって操作しやすい可能性がある。

```text
Brightness
Intensity
Control
Warmth
Tension
Resistance
```

## 13. 研究上の問い

本研究の中心的な問いは以下である。

```text
LLM内部の感情CAA空間を、ユーザーが直接操作可能な連続UIに写像することで、
名前付き感情ラベルでは表現しにくい内的状態を、
より高い納得感で言語化できるか？
```

これは感情分類の研究ではない。

むしろ、以下のような研究である。

```text
感情の外在化
感情の編集
感情の探索
感情の共同言語化
LLM内部表現を用いた内面記述インターフェース
```

---

## 14. 期待される貢献

このシステムが実現できれば、以下の貢献がある。

1. 名前付き感情ラベルに依存しない感情UIを提案できる
2. LLM内部の低次元感情空間を、人間が操作可能なインターフェースに変換できる
3. 「言葉にできない感情」を、LLMとの共同編集によって言語化できる
4. CAAを単なるsteering技術ではなく、内面表現の編集技術として応用できる
5. 感情を分類対象ではなく、連続的に探索・調整可能な表現空間として扱える

---

## 15. 現時点での結論

方法1と方法2は二択ではない。

最も有望なのは、両者を階層的に組み合わせる方法である。

```text
方法1:
共通の低次元感情空間
→ UIのメインミキサー

方法2:
各感情ごとの局所低次元空間
→ ニュアンス調整・複合感情生成・名前にできない感情の探索
```

これにより、ユーザーは既存の感情名を選ぶのではなく、自分の感情を連続的に探索しながら、LLMと一緒に言葉を作っていくことができる。

最終的な目標は、LLMがユーザーの感情を決めつけることではない。

ユーザーが「まだ言葉になる前の感情」を、操作し、聴き比べ、少しずつ調整しながら、自分にとって納得できる言葉へ変換できるようにすることである。
